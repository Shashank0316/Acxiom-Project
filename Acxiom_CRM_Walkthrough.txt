=========================================
AcxiomCRM - Architectural Walkthrough
=========================================

1. SYSTEM OVERVIEW & ARCHITECTURE
---------------------------------
AcxiomCRM is engineered as a monolithic, Layered Architecture web application using ASP.NET Core 8 MVC. The design prioritizes maintainability, security, and strict data validation, fulfilling all requirements outlined in the core business specifications.

- Presentation Layer: Server-rendered Razor views (.cshtml) combined with Bootstrap 5 for responsiveness. Interactive data visualizations are powered by Chart.js.
- Business Logic Layer: Fat models using Data Annotations for strict validation rules, supplemented by dedicated service classes (e.g., ILeadConversionService) for complex transactional operations.
- Data Access Layer: Entity Framework (EF) Core serving as the ORM, abstracting the underlying relational database. It integrates seamlessly with ASP.NET Core Identity.

2. SECURITY & AUTHORIZATION
---------------------------
Security is integrated at multiple levels:
- Authentication: ASP.NET Core Identity handles password hashing and user sessions. The password policy is strictly configured (min 8 characters, complex characters required) alongside a robust lockout policy (5 failed attempts locks the account for 15 minutes) to prevent brute-force attacks.
- Role-Based Access Control (RBAC): Every controller and API endpoint leverages the `[Authorize]` attribute. Data queries dynamically filter based on ClaimsPrincipal evaluation:
    * Admin & Manager: Full visibility across the dataset.
    * Sales Executive: Strict tenant-isolation at the row level; users can only query, view, or modify records explicitly assigned to their `AssignedToId`.
- Injection Prevention: EF Core utilizes parameterized queries by default, entirely mitigating SQL injection vectors.
- CSRF Protection: All state-mutating MVC forms utilize the `[ValidateAntiForgeryToken]` attribute.

3. DATA VALIDATION
------------------
Validation is executed in a dual-layer approach to ensure data integrity:
- Client-Side: Unobtrusive jQuery validation provides immediate UI feedback based on HTML5 data-val attributes generated by Razor.
- Server-Side: `ModelState.IsValid` checks are strictly enforced in every POST controller action. Business logic rules, such as preventing users from setting an Opportunity's "Expected Close Date" in the past, are explicitly evaluated on the server before database commits.

4. TRANSACTIONS & CONCURRENCY
-----------------------------
A critical business flow is the "Lead-to-Customer" conversion. This is handled by a dedicated `LeadConversionService`.
- To prevent race conditions or partial data writes (e.g., creating a Customer but failing to update the Lead), the logic is wrapped in `_context.Database.BeginTransactionAsync()`. 
- The system guarantees ACID compliance. If any step fails, the entire conversion rolls back, ensuring the database never enters an inconsistent state.

5. RESTful API
--------------
AcxiomCRM provides a robust API for integrations, located in the `Controllers/Api` namespace.
- Rather than exposing EF Core domain entities directly, the API heavily utilizes Data Transfer Objects (DTOs). This decouples the database schema from the API contract and prevents over-posting attacks.
- The API is secured under the same RBAC and JWT/Cookie authentication schemes as the MVC application.

6. AUDIT LOGGING
----------------
To maintain compliance and track modifications, an append-only `AuditLog` table is utilized. Every state-changing action (Create/Update/Convert) across both the MVC UI and the API explicitly generates an audit record tracking the `UserId`, `EntityName`, `Action`, timestamps, and IP addresses before `SaveChangesAsync()` is called.

7. AUTOMATED TESTING
--------------------
The solution includes a comprehensive xUnit test suite (`AcxiomCRM.Tests`). It utilizes an in-memory SQLite database (`DataSource=:memory:`) to run true integration tests. The test suite aggressively validates the Role-Based Authorization filters and ensures the Lead Conversion transaction safely rolls back under failure conditions.
